## Context

動機は `proposal.md` の Why。振る舞いの契約は `specs/task/spec.md`。正本は `openspec/specs/task/spec.md` である。

いまのタスク JSON は `id`、`title`、`assigneeId`、`done`、`createdAt` である。PATCH が書くのは `assigneeId` と `done` だけである。`/` の「タスクを登録」はナビゲーションの中にある。DynamoDB のタスクテーブルは PK `id` のままである。

## Goals

- `body`、`dueOn`、`completedAt` を、既存の PATCH と画面に足すこと
- 期限超過と、右下の「タスクを登録」を、文言を変えずに出すこと
- 422 と 404 は pytest、画面の新しい断言は既存の `frontend/e2e/` に足すこと

## Non-Goals

- タイトルの編集、Markdown 描画、画像、添付、検索、ログイン
- 新しい API パス、新しい AWS サービス、`infra/` の編集
- screenshot テスト、e2e の 422
- `cdk deploy`、git commit、git push、実 URL
- `AGENTS.md`、`README.md`、`docs/rules/project-rules-serena.md`、アーカイブ済み change の本文の編集
- 1本目から 6本目の編集
- ルートの Playwright 見本を合否にすること

## Decisions

### 1. 項目は同じタスクに足し、読むときに欠けを補う

- 決定: 新しいパスは足さない。`infra/` は編集しない。新規タスクは `body`、`dueOn`、`completedAt` を保存する。保存済みでそれらのキーが無いタスクは、GET と PATCH の応答を作るときに `body` を `""`、`dueOn` と `completedAt` を null にする。ストアの古い項目を書き戻す移行はしない
- 理由: DynamoDB は項目の追加にテーブル変更が要らない。欠けたキーを毎回書き戻すと、読むだけで保存が変わる
- 代替: 別 API を足す → 契約で足さない。読み込み時にテーブルを更新する → 読む操作が書き込みになる

### 2. 内容は平文、期限は日付、完了日は遷移のときだけサーバが付ける

- 決定: `body` は文字列だけを受け、両端を strip して保存する。中の改行は残す。画面はテキストのまま出し、HTML にはしない。ラベルは「内容」とする。`dueOn` は `datetime.date.fromisoformat` で実在する `YYYY-MM-DD` だけを保存する。空文字と null は null である。省略は保存済みを変えない。画面のラベルは「期限」とし、入力は `type="date"` とする。空の入力は期限なしとして送る。`completedAt` は `done` が false から true になったときだけ `datetime.now(timezone.utc).isoformat()` の UTC 表記を付ける。true の再送は元の値を残す。true から false は null である。クライアントの `completedAt` は捨てる。画面は入力欄にせず、値があるときだけ「完了日」と、その文字を出す
- 理由: strip 後の空を許す契約と、別の日付の形を拒否する契約を、サーバの検証で揃える。`type="date"` の値は `YYYY-MM-DD` である
- 代替: Markdown を描画する → 契約で描画しない。完了日を利用者が選ぶ → 契約でクライアントは決めない

### 3. 期限超過は画面のローカル日付で判定する

- 決定: 一覧のカードは、1 段目がタイトル、2 段目が担当者名と完了と作成日時のままである。期限、完了日、「期限超過」は、その下の別の行で、カードのリンクの中に出す。`body` の全文は出さない。超過は、`done` が false かつ `dueOn` が `new Date()` のローカル暦日より前のときだけである。当日は超過にしない。左の線は `border-left: 4px solid #b45309` とする。未完了の `#1d4ed8`、完了の `#6b7280`、削除の `#9f1239` は変えない
- 理由: 期限は時刻を持たない日付である。UTC の日付にすると、利用者の当日とずれる
- 代替: サーバが超過を判定する → サーバは利用者のローカル日付を知らない。色だけで示す → 契約で文言を出す

### 4. 登録リンクは右下に固定し、メンバーはナビに残す

- 決定: 「タスクを登録」をナビゲーションから外し、`/` のビューポート右下に `position: fixed` で置く。右と下は `1rem` とする。文言と `href="/new"` は変えない。「メンバー」はナビゲーションに残す。一覧の下に `padding-bottom: 5rem` を置き、最後のカードがボタンに隠れないようにする
- 理由: ナビに残すと右下固定にならない。余白が無いと最後のカードが隠れる
- 代替: 右下にもナビにも同じリンクを置く → 導線が二つになる

## Risks / Trade-offs

- [PATCH の見出しは「assigneeId と done だけ」のままである] → アーカイブ時に正本の見出しと一致させるためである。実装は本文とシナリオに従い、`body` と `dueOn` も書く
- [シナリオ名「成功は 5 キーを返す」「両方省略は拒否する」を残す] → 同じ名前のシナリオを本文ごと置き換える。成功時のキーは 8 つである。省略の 422 は 4 項目とも無いときである
- [ラベル「内容」「期限」は画面のための名前である] → 契約は項目名 `body` と `dueOn` である。e2e はこのラベルで入力する
