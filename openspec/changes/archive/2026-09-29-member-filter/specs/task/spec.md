## MODIFIED Requirements

### Requirement: タスク一覧は / である
システムは画面 `/` でタスク一覧を必須で出す。並びは `createdAt` の降順で必須である。絞り込みのあとでも、その順のままであることが必須である。各項目は担当者名、完了、作成日時を必須で示す。カードからそのタスクの詳細 `/tasks/:id` へ必須で遷移する。タスクが無いとき、および絞った結果が 0 件のときは、タスクが無いことが分かる表示のままであることが必須である。そのときも select は残すことが必須である。タスク登録への導線は必須である。完了済みのタスクも、絞り込みの対象に入るなら一覧に残すことが必須である。一覧に削除を置いてはならない。完了の切り替えを置いてはならない。担当者の変更を置いてはならない。一覧をメンバーで絞る select を置くことが必須である。初期選択は「全員」であることが必須である。「全員」の値はメンバーの `id` ではないことが必須である。続く選択肢は GET `/api/members` のメンバーであることが必須である。表示は `name`、値は `id` であることが必須である。並びは API の順であることが必須である。同名でも `id` で区別することが必須である。「全員」のときは全件を出すことが必須である。1 人を選んだときは、その `id` と `assigneeId` が一致するタスクだけを出すことが必須である。絞り込みは、既存の GET `/api/tasks` 全件に対する画面の処理であることが必須である。新しい API、別の一覧 API、クエリ付きの GET を足してはならない。URL に絞り込みを載せてはならない。`/` を開いたとき、および詳細から一覧へ戻ったときの初期値は「全員」であることが必須である。選んだ `id` のメンバーが無いときは「全員」に戻すことが必須である。

#### Scenario: 空のタスク一覧
- **とき** タスクがまだ無い状態で `/` を開く
- **ならば** タスクが無いことが分かる
- **かつ** タスク登録への導線がある
- **かつ** 削除操作は無い
- **かつ** select があり、選択は「全員」である

#### Scenario: 一覧は新しいタスクが上である
- **とき** 作成日時が異なるタスクが 2 件以上ある状態で `/` を開く
- **ならば** `createdAt` が新しいタスクが上に出る
- **かつ** 各項目に担当者名、完了、作成日時が出る
- **かつ** カードからそのタスクの詳細へ遷移できる
- **かつ** 一覧に削除は無い

#### Scenario: 完了済みも一覧に残る
- **とき** `done` が true のタスクと false のタスクがある状態で `/` を開く
- **ならば** 両方とも一覧に出る
- **かつ** 一覧に完了の切り替えは無い
- **かつ** 一覧に担当者の変更は無い

#### Scenario: 初期は全員である
- **とき** 担当者が異なるタスクがある状態で `/` を開く
- **ならば** select の選択は「全員」である
- **かつ** 「全員」の値は、どのメンバーの `id` でもない
- **かつ** 全件が出る
- **かつ** URL に絞り込みは無い

#### Scenario: 選択肢はメンバーの id である
- **とき** メンバーが 2 人以上いる状態で `/` の select を見る
- **ならば** 「全員」の次に、GET `/api/members` のメンバーが API の順で並ぶ
- **かつ** 各メンバーの表示は `name` である
- **かつ** 各メンバーの値は `id` である

#### Scenario: 同名でも id で区別する
- **とき** 同じ `name` で `id` が異なるメンバーが 2 人いる状態で `/` の select を見る
- **ならば** 選択肢は 2 つある
- **かつ** 値は互いに異なる `id` である

#### Scenario: 1 人を選ぶとその担当だけが残る
- **とき** 担当者が異なるタスクがあり、その中に完了済みがある状態で、1 人の `id` を選ぶ
- **ならば** 出るタスクは、その `id` と `assigneeId` が一致するものだけである
- **かつ** その人の完了済みも残る
- **かつ** 並びは `createdAt` の降順のままである
- **かつ** 他の担当のタスクは出ない
- **かつ** URL に絞り込みは無い

#### Scenario: 全員に戻すと全件に戻る
- **とき** 1 人を選んだあと、「全員」に戻す
- **ならば** 全件が出る
- **かつ** 完了済みも出る

#### Scenario: 詳細から戻ると全員である
- **とき** 1 人を選んだ一覧から詳細を開き、一覧へ戻る
- **ならば** 選択は「全員」である
- **かつ** 全件が出る
- **かつ** URL に絞り込みは無い

#### Scenario: 選んだメンバーが無いと全員に戻る
- **とき** 選んでいる `id` のメンバーが GET `/api/members` に無い
- **ならば** 選択は「全員」に戻る
- **かつ** 全件が出る

#### Scenario: 0 件でも select は残る
- **とき** 担当タスクが無いメンバーを選ぶ
- **ならば** タスクが無いことが分かる
- **かつ** select は残る
- **かつ** その選択は、選んだメンバーのままである

### Requirement: 一段目では絞り込みと担当者変更と完了切替をしない
メンバー絞り込みは、画面 `/` の select で行うことが必須である。選択したメンバーの値は、そのメンバーの `id` であることが必須である。「全員」の値はメンバーの `id` ではないことが必須である。絞り込み用の API を足してはならない。担当者変更と完了の切り替えは、詳細画面と `PATCH /api/tasks/{id}` だけで行うことが必須である。一覧に担当者の変更と完了の切り替えを置いてはならない。タスク POST の `done` は false のままであることが必須である。

#### Scenario: 一覧は全員のタスクである
- **とき** 担当者が異なるタスクが複数あり、その中に完了済みがある状態で `/` を開く
- **ならば** 絞り込みの select があり、選択は「全員」である
- **かつ** 全部のタスクが出る
- **かつ** 完了済みも出る
- **かつ** 一覧に担当者の変更は無い
- **かつ** 一覧に完了の切り替えは無い

#### Scenario: 完了は false のままである
- **とき** クライアントがタスクを POST する
- **ならば** 保存された `done` は false である
- **かつ** 詳細と PATCH で切り替えていないタスクの `done` は false のままである

### Requirement: 画面の合否は Playwright Test である
画面の合否は `frontend/e2e/` の Playwright Test であることが必須である。ブラウザは Chromium だけであることが必須である。サーバの 422 と 404 は backend の pytest が正であることが必須である。e2e に 422 を足してはならない。e2e は、担当者変更、完了の切り替え、文言「完了」と「未完了」、完了済みが一覧に残ることを断言することが必須である。e2e は、絞り込みの初期が「全員」であること、1 人を選ぶとその担当のタスクだけが残り完了済みも残ること、「全員」に戻すと全件に戻ること、URL に絞り込みが無いことを断言することが必須である。リポジトリ直下の `playwright.config.ts` と `tests/example.spec.ts` は初期化の見本である。合否に使ってはならない。見本の設定を `frontend/` へ移してはならない。見本を消してはならない。Playwright MCP は下書きである。合否にしてはならない。

#### Scenario: 合否は Chromium の e2e である
- **とき** 画面の合否を確認する
- **ならば** 実行場所は `frontend/e2e/` である
- **かつ** ブラウザは Chromium だけである
- **かつ** サーバの 422 と 404 は pytest が正である
- **かつ** e2e に 422 は無い

#### Scenario: 見本と MCP は合否ではない
- **とき** リポジトリ直下の見本と Playwright MCP を確認する
- **ならば** 見本は合否に使っていない
- **かつ** 見本の設定は `frontend/` に移していない
- **かつ** 見本は残っている
- **かつ** Playwright MCP は合否ではない

#### Scenario: e2e は担当者変更と完了切替を断言する
- **とき** `frontend/e2e/` の Playwright Test を確認する
- **ならば** 担当者の変更が断言されている
- **かつ** 完了の切り替えが断言されている
- **かつ** 文言「完了」と「未完了」が断言されている
- **かつ** 完了済みが一覧に残ることが断言されている

#### Scenario: e2e はメンバー絞り込みを断言する
- **とき** `frontend/e2e/` の Playwright Test を確認する
- **ならば** 初期が「全員」であることが断言されている
- **かつ** 1 人を選ぶと、その担当のタスクだけが残り、完了済みも残ることが断言されている
- **かつ** 「全員」に戻すと全件に戻ることが断言されている
- **かつ** URL に絞り込みが無いことが断言されている
