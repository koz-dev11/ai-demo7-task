## Context

動機は `proposal.md` の Why。振る舞いの契約は `specs/task/spec.md`。正本は `openspec/specs/task/spec.md` である。

二段目まで、画面 `/` は GET `/api/tasks` の全件を `createdAt` 降順で出す。担当者名は GET `/api/members` と `assigneeId` を画面で結ぶ。絞り込みは無い。詳細の担当者変更と完了切替、PATCH は二段目のままである。

この change が変えるのは、その一覧の見え方だけである。`backend/` と `infra/` は触らない。

## Goals

- `/` の select で、初期は「全員」、1 人のときはその `id` の担当タスクだけにすること
- 絞り込みを、既にある GET `/api/tasks` 全件の画面処理にすること
- 詳細から一覧へ戻ったとき、および選んだメンバーが無いとき、「全員」に戻ること
- 画面の合否を `frontend/e2e/` の Playwright Test（Chromium だけ）にすること

## Non-Goals

- `backend/` と `infra/` の編集。CDK、テーブル、Output、PATCH の変更
- 新しい API、別の一覧 API、クエリ付きの GET、URL への絞り込み
- 画面ルートの追加。`/new`、`/tasks/:id`、`/members` の操作変更
- 一覧への削除、担当者変更、完了切替
- ログイン、Cognito、検索箱、検索用 API、GSI、ソフト削除、カスケード削除、タイトル編集、タスク本文、他タスクの再割り当て、新しい AWS サービス
- `cdk deploy`、git commit、git push、実 URL
- `AGENTS.md`、`README.md`、`docs/rules/project-rules-serena.md`、アーカイブ済み change の本文の編集
- 1本目から 6本目の編集
- ルートの Playwright 見本を合否にすること、見本を消すこと、見本の設定を `frontend/` へ移すこと、Playwright MCP を合否にすること
- サーバの 422 を e2e の正にすること

## Decisions

### 1. 「全員」の値は空文字である

- 決定: select の先頭は表示「全員」、値は空文字である。メンバーの選択肢の値は、GET `/api/members` が返した `id` である。表示は `name` である。並びは API の順のままである。同じ `name` でも option は分け、値の `id` で区別する。空文字はメンバーの `id` ではない
- 理由: メンバーを選んだときの値は `id` である。「全員」をどこかの `id` にすると、その人と全員が区別できない
- 代替: 「全員」の値に `"all"` のような印を使う → 空文字で足りる。先頭以外の並びを画面で並べ替える → API の順という契約とずれる

### 2. 絞り込みは一覧の状態だけである

- 決定: 選択は `frontend/src/pages/ListPage.tsx` の状態である。初期値は空文字である。URL、`sessionStorage`、親の画面には持たない。`/` を離れるとこの状態は消え、詳細から戻って一覧が開いたときの初期値は「全員」である。GET `/api/tasks` の全件のうち、空文字なら全部、そうでなければ `assigneeId` がその値のタスクだけを、受け取った順のまま出す。並び替えはしない。GET `/api/members` の結果に、選んでいる `id` が無いときは空文字に戻す。0 件のときの文言は、既存の「タスクはまだありません。」のままである。select は残す。ラベルは「メンバー」とする。一覧に削除、担当者の select、完了の checkbox は置かない。`frontend/src/api.ts` に新しい関数は足さない
- 理由: クエリを足すと URL に絞り込みが載る。一覧を残したまま詳細を開く構造ではないので、戻ったときは初期値「全員」になる。0 件の文言を変えると、タスクが無いときと絞った結果が空のときで表示が分かれる
- 代替: 絞り込みをクエリにする → 契約で載せない。0 件のとき select を隠す → 契約で残す

### 3. 他の画面とサーバは二段目のままである

- 決定: `/new`、`/tasks/:id`、`/members` の操作は変えない。画面ルートは増やさない。`backend/` と `infra/` は編集しない。PATCH、422、404 の pytest は既存のままである。e2e に 422 を足さない。合否は `frontend/e2e/` の Chromium だけである。ルートの見本と Playwright MCP は合否にしない
- 理由: 三段目の差は一覧の見え方だけである。422 と 404 は API の契約であり、この change は API を変えない
- 代替: 絞り込み用の GET を足す → 契約で足さない

## Risks / Trade-offs

- [Requirement の見出しは「絞り込みをしない」のままである] → アーカイブ時に正本の見出しと一致させるためである。実装は本文とシナリオに従う
- [一覧を離れると絞り込みが消える] → 詳細から戻ったときの初期値は「全員」である。URL に残さない
- [同名の option は表示だけでは区別できない] → 値は `id` である。e2e が同名を選ぶときは、表示文字ではなく値で選ぶ
- [担当タスクが残るメンバーは削除できない] → 選んだメンバーを消して「全員」に戻す確認は、担当タスクが無いメンバーで行う。422 は e2e に足さない
