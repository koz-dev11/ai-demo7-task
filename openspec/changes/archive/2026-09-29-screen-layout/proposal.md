## Why

三段までの画面は、登録・一覧・詳細・絞り込みが通る。項目は縦に並ぶだけで、カードの区切り、完了の色、フォームの並びが揃っていない。この change は、文言と操作を変えずに見た目だけを整える。

## What Changes

- 一覧のカードは、枠と余白のある塊にする。中は 2 段である。1 段目はタイトルだけを大きく出す。2 段目は担当者名、「完了」または「未完了」、作成日時を小さく横に並べる。箇条書きの黒丸は出さない。カードのリンクの中に、タイトル、担当者名、完了の文言、作成日時の文字が残ることが必須である
- 「完了」は灰色寄りの色、「未完了」はそれとは別の色で区別する。文字は変えない。作成日時は UTC ISO8601 の文字のまま、小さい灰色の文字にする
- 「メンバー」の select は、ナビゲーションの下に 1 行とって置く。ラベル「メンバー」、先頭の表示「全員」、値は空文字、続きは `name` と `id`、の契約は変えない
- 詳細は、項目ごとにラベルを上、操作を下に置く。担当者名の文字は残す。完了の文言と checkbox は同じ行に置く。checkbox の名前「完了を切り替える」は変えない
- 「削除」は内容から離し、登録ボタンとは違う色にする。確認の文言「削除しますか？」は変えない
- メンバーの 1 行は、名前を左、作成日時を小さく、削除を右端にする
- 登録フォームは、ラベルを上、入力欄をその下に幅いっぱいで置き、ボタンをその下に置く。エラーは入力欄の直下に置く
- 戻るリンク「タスク一覧」は、それがある画面の先頭で同じ位置にする。本文の幅は 40rem のままである。背景は白に近く、文字は黒に近くする。ボタンと入力欄は、キーボードで選んだとき枠が分かることが必須である
- 見つからない表示も、他の画面と同じ幅の中に置く。文言「見つかりません。」は変えない
- 画面ルート、API、絞り込みの仕様、表示する文言、`backend/`、`infra/` は変えない。一覧に削除、担当者の select、完了の checkbox は置かない
- 画面の合否は、既存の `frontend/e2e/` の Playwright Test（Chromium だけ）が成功することである。見た目のための新しい screenshot テストは足さない。サーバの 422 と 404 は既存の pytest が正である。e2e に 422 を足さない

## Capabilities

### New Capabilities

- （なし。capability `task` は正本 `openspec/specs/task/spec.md` にある）

### Modified Capabilities

- `task`: 見た目の要求を ADDED する。既存 Requirement の文言と操作は変えない

## Impact

- 企画成果物: `openspec/changes/screen-layout/` の proposal / specs / design / tasks。確認後の apply で画面の見た目だけを足す
- 実装の置き場: `frontend/` のスタイルと、並びのための印。`backend/` と `infra/` は編集しない
- 画面ルートは `/`、`/new`、`/tasks/:id`、`/members` のままである。API は三段目のままである
- リポジトリ直下の `playwright.config.ts` と `tests/example.spec.ts` は初期化の見本である。合否に使わない。見本の設定を `frontend/` へ移さない。見本は消さない
- `AGENTS.md`、`README.md`、`docs/rules/project-rules-serena.md`、アーカイブ済み change の本文は編集しない。実 URL は書かない
- 1本目から 6本目は編集しない
- この change に含めないもの: 検索箱、新しい API、ログイン、Cognito、`cdk deploy`、git commit、git push、実 URL
