## Context

動機は `proposal.md` の Why。見た目の契約は `specs/task/spec.md`。正本は `openspec/specs/task/spec.md` である。

三段まで、画面は `/`、`/new`、`/tasks/:id`、`/members` である。本文の幅は `main` の 40rem である。一覧のカードはリンクの中にタイトル、担当者名、完了の文言、作成日時を持つ。詳細の checkbox は、ラベルの外に置き `htmlFor` で結んでいる。未知のパスの「見つかりません。」は `main` の外にある。

この change が変えるのは見た目と、その並びに必要な印だけである。文言、操作、絞り込み、API は変えない。

## Goals

- カード、完了の色、フォーム、詳細、メンバー行、戻る位置、地の色を、delta の見た目にすること
- キーボードで選んだボタンと入力欄の枠が分かること
- 既存の `frontend/e2e/` の Playwright Test（Chromium だけ）が成功したままであること

## Non-Goals

- 画面ルート、API、絞り込み、表示する文言の変更
- `backend/` と `infra/` の編集。CDK、テーブル、Output、PATCH の変更
- 一覧への削除、担当者の select、完了の checkbox
- 新しい screenshot テスト。e2e への 422。サーバの 422 と 404 を e2e の正にすること
- ログイン、Cognito、検索箱、新しい API、`cdk deploy`、git commit、git push、実 URL
- `AGENTS.md`、`README.md`、`docs/rules/project-rules-serena.md`、アーカイブ済み change の本文の編集
- 1本目から 6本目の編集
- ルートの Playwright 見本を合否にすること、見本を消すこと、見本の設定を `frontend/` へ移すこと

## Decisions

### 1. 見た目は既存の CSS と、並びのための印だけである

- 決定: 色、枠、余白、段組、幅、フォーカスは `frontend/src/index.css` に書く。DOM を動かすのは、戻るリンクを先頭へ置くこと、登録エラーを入力欄の直下へ置くこと、詳細の完了の文言と checkbox を同じ行にすること、未知のパスを `main` で包むことだけである。新しい文言、役割、ルートは足さない。新しいパッケージは足さない
- 理由: 契約が変えるのは見え方である。文言を足すと、既存の e2e が見ている名前とずれる
- 代替: 画面ごとに別の CSS ファイルを足す → いまの画面数では `index.css` で足りる

### 2. カードはリンクの中を 2 段にする

- 決定: カードのリンクの子は、いまどおりタイトル、担当者名、完了の文言、作成日時である。1 つ目を幅いっぱいに大きくし、残りの 3 つをその下で横に並べる。一覧の `ul` とメンバーの `ul` は黒丸を出さない。完了の文字色は `#6b7280`、未完了の文字色は `#1d4ed8` とする。作成日時は文字を変えず、小さい `#6b7280` とする
- 理由: リンクの外へ文字を出すと、カードのリンクの中に文字がある契約とずれる。未完了を青にすると、灰色の完了と区別できる
- 代替: 2 段目を別要素で包んでから色を付ける → 子の順を保てば、包まなくても段は作れる。包む場合も、包みはリンクの中に置く

### 3. 地の色、削除、フォーカス、幅

- 決定: 背景は `#ffffff`、本文の文字は `#1a1a1a` とする。`main` の最大幅は 40rem のままである。「削除」は内容から `2rem` 以上離し、背景を `#9f1239`、文字を白にする。「登録する」は背景 `#1a1a1a`、文字を白にする。ボタン、入力欄、select、checkbox は、キーボードで選んだとき `outline: 2px solid #1d4ed8` が見えるようにする。マウスのクリックだけではこの枠を要求しない
- 理由: 削除と登録が同じ色だと、契約の「違う色」を満たさない。幅を変えると 40rem の契約とずれる
- 代替: 削除を枠線だけにする → 登録の塗りと違いは出るが、離した位置と合わせて塗り分けた方が一目で分かる

### 4. フォームと詳細と戻る位置

- 決定: `/new` と `/members` のラベルは上、入力欄はその下で幅いっぱい、エラーの `alert` は入力欄の直下、「登録する」はその下である。`/new`、`/tasks/:id`、`/members` では、「タスク一覧」のリンクを `main` の先頭に置く。見出しはその後である。詳細の「担当者」は select の上に置く。担当者名の段落は残す。完了の段落 `done-state` と checkbox を同じ行にする。checkbox はラベルの中に入れず、名前「完了を切り替える」の `htmlFor` は維持する。メンバーの行は、名前を左、作成日時を小さく、削除を右端にする。未知のパスは `main` の中の「見つかりません。」にする。`/` の「メンバー」の select は、ナビゲーションの次のブロックで 1 行にする
- 理由: エラーがボタンの後にあると、入力欄の直下という契約とずれる。checkbox をラベルの中に入れると、クリックが二度切り替わる。未知のパスが `main` の外だと、40rem の幅に入らない
- 代替: 戻るリンクを共通部品に切り出す → 3 画面の先頭に同じリンクを置くだけで足りる。新しいルートは足さない

## Risks / Trade-offs

- [色の指定は見た目の選択である] → 完了は灰色、未完了は青、削除は赤、登録は黒で固定する。文字は変えない
- [カードの段組で、リンクの accessible name の並びが変わる] → 入っている文字は変えない。既存の e2e はタイトルと「完了」「未完了」を見ている
- [checkbox を行にまとめるときにラベルへ入れる] → 入れない。`htmlFor` のままにする
