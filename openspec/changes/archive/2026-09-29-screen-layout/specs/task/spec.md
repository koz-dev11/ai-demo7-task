## ADDED Requirements

### Requirement: 一覧のカードは2段の塊である
画面 `/` の各タスクは、枠と余白を持つ塊であることが必須である。中は 2 段であることが必須である。1 段目はタイトルだけを、他の文字より大きく出すことが必須である。2 段目は担当者名、「完了」または「未完了」、作成日時を、1 段目より小さく横に並べることが必須である。箇条書きの黒丸を出してはならない。カードのリンクの中に、タイトル、担当者名、完了の文言、作成日時の文字が入っていることが必須である。一覧に削除、担当者の select、完了の checkbox を置いてはならない。

#### Scenario: カードは2段で黒丸が無い
- **とき** タスクが 1 件以上ある状態で `/` を開く
- **ならば** 各タスクは枠と余白のある塊である
- **かつ** 1 段目はタイトルだけが大きく出る
- **かつ** 2 段目に担当者名、完了の文言、作成日時が小さく横に並ぶ
- **かつ** 箇条書きの黒丸は無い
- **かつ** それらの文字は、そのタスクの詳細へ進むリンクの中にある
- **かつ** 一覧に削除、担当者の select、完了の checkbox は無い

### Requirement: 完了と未完了は色で区別する
「完了」と「未完了」の文字は変えてはならない。完了は灰色寄りの色であることが必須である。未完了は、完了とは別の色であることが必須である。一覧と詳細の両方であることが必須である。

#### Scenario: 未完了は完了と色が違う
- **とき** `done` が false のタスクを一覧と詳細で見る
- **ならば** 文言は「未完了」である
- **かつ** その色は、完了の灰色寄りとは別である

#### Scenario: 完了は灰色寄りである
- **とき** `done` が true のタスクを一覧と詳細で見る
- **ならば** 文言は「完了」である
- **かつ** その色は灰色寄りである

### Requirement: 作成日時は ISO8601 の小さい灰色である
作成日時の表示は、いまの UTC ISO8601 の文字のままであることが必須である。別の日付の形にしてはならない。小さい灰色の文字であることが必須である。一覧、詳細、メンバーの行で、すでに出している作成日時が対象である。

#### Scenario: 作成日時の文字は変えない
- **とき** 作成日時が出ている画面を開く
- **ならば** 文字は UTC ISO8601 のままである
- **かつ** 小さい灰色の文字である

### Requirement: メンバーの select はナビゲーションの下にある
画面 `/` の「メンバー」の select は、ナビゲーションの下に 1 行とって置くことが必須である。ラベルは「メンバー」であることが必須である。先頭の表示は「全員」、値は空文字であることが必須である。続く選択肢の表示は `name`、値は `id` であることが必須である。絞り込みの仕様は変えてはならない。

#### Scenario: select はナビの下の1行である
- **とき** `/` を開く
- **ならば** 「メンバー」の select はナビゲーションの下に 1 行で出る
- **かつ** 先頭の表示は「全員」で、値は空文字である
- **かつ** 続く選択肢の表示は `name`、値は `id` である

### Requirement: 詳細はラベルが上で操作が下である
画面 `/tasks/:id` は、項目ごとにラベルを上、操作を下に置くことが必須である。担当者名の文字は残すことが必須である。完了の文言と checkbox は同じ行に置くことが必須である。checkbox の名前「完了を切り替える」は変えてはならない。

#### Scenario: 担当者はラベルが上である
- **とき** 存在するタスクの詳細を開く
- **ならば** 「担当者」のラベルは、その select の上にある
- **かつ** 担当者名の文字が残る

#### Scenario: 完了の文言と checkbox は同じ行である
- **とき** 存在するタスクの詳細を開く
- **ならば** 「完了」または「未完了」と、checkbox が同じ行にある
- **かつ** checkbox の名前は「完了を切り替える」である

### Requirement: 削除は内容から離れ登録とは色が違う
「削除」は、その画面の内容から離して置くことが必須である。登録ボタンとは違う色であることが必須である。確認の文言「削除しますか？」は変えてはならない。

#### Scenario: 削除は離れていて色が違う
- **とき** 詳細、またはメンバー画面で「削除」を見る
- **ならば** 「削除」は内容から離れている
- **かつ** 「登録する」とは違う色である
- **かつ** 確認の文言は「削除しますか？」のままである

### Requirement: メンバーの1行は名前、日時、削除である
画面 `/members` の 1 行は、名前を左、作成日時を小さく、削除を右端に置くことが必須である。箇条書きの黒丸を出してはならない。

#### Scenario: メンバー行は左右に分かれる
- **とき** メンバーが 1 人以上いる状態で `/members` を開く
- **ならば** 名前は左にある
- **かつ** 作成日時は小さい
- **かつ** 削除は右端にある
- **かつ** 箇条書きの黒丸は無い

### Requirement: 登録フォームは縦に積む
登録フォームは、ラベルを上、入力欄をその下に幅いっぱいで置き、ボタンをその下に置くことが必須である。エラーは入力欄の直下に置くことが必須である。対象は `/new` と `/members` である。ラベル「タイトル」「名前」、ボタン「登録する」、エラーの文言は変えてはならない。

#### Scenario: 入力の直下にエラーが出る
- **とき** `/new` でタイトルが空のまま登録しようとする
- **ならば** ラベル「タイトル」は入力欄の上にある
- **かつ** 入力欄は幅いっぱいである
- **かつ** エラーは入力欄の直下にある
- **かつ** 「登録する」はその下にある
- **かつ** エラーの文言は「タイトルは必須です」のままである

#### Scenario: メンバー登録も同じ並びである
- **とき** `/members` で名前が空のまま登録しようとする
- **ならば** ラベル「名前」は入力欄の上にある
- **かつ** 入力欄は幅いっぱいである
- **かつ** エラーは入力欄の直下にある
- **かつ** 「登録する」はその下にある
- **かつ** エラーの文言は「名前は必須です」のままである

### Requirement: 画面の幅と地と戻る位置は揃える
本文の幅は 40rem のままであることが必須である。背景は白に近いことが必須である。文字は黒に近いことが必須である。ボタンと入力欄は、キーボードで選んだとき枠が分かることが必須である。戻るリンク「タスク一覧」がある画面では、そのリンクを画面の先頭の同じ位置に置くことが必須である。リンクの文言は変えてはならない。見つからない表示は、他の画面と同じ幅の中に置くことが必須である。文言「見つかりません。」は変えてはならない。

#### Scenario: 戻るリンクは先頭で同じ位置である
- **とき** `/new`、`/tasks/:id`、`/members` を開く
- **ならば** 「タスク一覧」は各画面の先頭の同じ位置にある
- **かつ** 文言は「タスク一覧」のままである

#### Scenario: キーボードで枠が分かる
- **とき** ボタン、または入力欄をキーボードで選ぶ
- **ならば** 選んだ枠が分かる

#### Scenario: 見つからない表示は同じ幅である
- **とき** 存在しないパスを開く
- **ならば** 「見つかりません。」が、他の画面と同じ幅の中に出る
- **かつ** 文言は「見つかりません。」のままである

### Requirement: 見た目の合否は既存の e2e である
この change の画面の合否は、既存の `frontend/e2e/` の Playwright Test が成功することであることが必須である。ブラウザは Chromium だけであることが必須である。見た目のための新しい screenshot テストを足してはならない。サーバの 422 と 404 は既存の pytest が正であることが必須である。e2e に 422 を足してはならない。

#### Scenario: screenshot テストは足さない
- **とき** この change の画面の合否を確認する
- **ならば** 既存の `frontend/e2e/` の Playwright Test を Chromium だけで実行する
- **かつ** 見た目のための新しい screenshot テストは無い
- **かつ** e2e に 422 は無い
