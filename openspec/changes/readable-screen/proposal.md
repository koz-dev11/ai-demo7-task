## Why

`task-content` でカードと詳細に足した期限・完了日・期限超過が、`screen-layout` の余白のまま詰まっている。ナビの「タスクを登録」もテキストリンクのままである。文言と操作は変えず、見た目の密度だけを直す。

## What Changes

- 一覧 `/` のカードは、1 段目をタイトルだけ大きく出す。2 段目は担当者名、「完了」または「未完了」、作成日時を小さく横に並べ、作成日時は UTC ISO8601 の小さい灰色のまま、その行の右端に寄せる
- `dueOn`、`completedAt`、「期限超過」はカードの中の別の行に出す。その行の項目のあいだに間隔を置く。日付・「完了日」・「期限超過」を隙間なくつなげない。期限の表示は `YYYY-MM-DD` のままである。一覧に「期限」というラベルは足さない
- 期限超過の左の線は `#b45309` のままである。「期限超過」の文字色も `#b45309` にする。色だけにはしない
- カードのリンクの中に、タイトル、担当者名、完了の文言、作成日時を残す。一覧に削除、担当者の select、完了の checkbox は置かない。`body` の全文は出さない
- 詳細 `/tasks/:id` の欄は、上から担当者、完了の行、期限、完了日、作成日時、内容、「削除」の順にする。各項目はラベルを上、操作を下に置く。欄と欄のあいだに余白を置く。期限の `type="date"` は本文幅いっぱいに伸ばさない。完了日は入力欄にせず、「完了日」のあとに空白を挟んで UTC ISO8601 とする。作成日時に新しいラベルは足さない。内容の `textarea` は平文のまま、最小の高さを持たせる。「削除」は内容から離し、背景 `#9f1239`、文字は白のままである。確認は「削除しますか？」のままである
- `/new` と `/members` の登録フォームは、ラベルを上、入力欄をその下に幅いっぱいで置き、ボタンをその下に置く。エラーは入力欄の直下に置く。欄と欄のあいだに余白を置く。内容の `textarea` は、詳細と同じ最小の高さにする。ラベル「タイトル」「名前」「内容」「期限」、ボタン「登録する」、エラー「タイトルは必須です」「名前は必須です」は変えない
- 絞り込みの「メンバー」は、ナビゲーションの下で、ラベルと select を横一列にする。ラベルは「メンバー」、先頭は「全員」で値は空文字、続きは `name` と `id` のままである。この横並びで、登録フォームの縦積みは崩さない
- 「タスクを登録」は `/` のナビゲーションに残す。順は「メンバー」、その次が「タスクを登録」である。文言と `/new` は変えない。右下には固定しない。固定のための一覧下の余白は置かない。見た目だけ、登録ボタンと同じ黒地・白文字にする。要素はリンクのままである。class `register-link` は使わない
- `/members` の 1 行は、名前を左、作成日時を小さく、削除を右端にする。行のあいだを線で区切る。箇条書きの黒丸は出さない
- 本文の幅は 40rem のままである。背景は白に近く、文字は黒に近い。完了は `#6b7280`、未完了は `#1d4ed8`、削除は `#9f1239` のままである。ボタンと入力欄は、キーボードで選んだとき枠が分かる。戻るリンク「タスク一覧」は、それがある画面の先頭の同じ位置のままである。「見つかりません。」は変えない
- 画面の合否は `frontend/e2e/board.spec.ts` の Playwright Test（Chromium だけ）である。既存の断言は崩さない。見た目のための screenshot テストは足さない。e2e に 422 は足さない。サーバの 422 と 404 は pytest が正である
- 対象は `frontend/src/index.css` と、詳細の欄の上下だけである。`backend/` と `infra/` は編集しない。新しい API パスは無い。画面ルートは増やさない
